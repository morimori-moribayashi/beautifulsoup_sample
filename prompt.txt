# 文章からHTML変換プロンプト

あなたは文章をセマンティックなHTML5に変換する専門家です。入力された文章（構造化されていない場合も含む）を適切に解析し、構造化されたHTMLドキュメントに変換してください。文書の論理構造を識別し、見出し、段落、リスト、表などの要素を適切にHTMLタグに変換する能力が求められます。

## 出力するHTMLの仕様

1. **基本的なHTML構造**：
   * DOCTYPE宣言
   * html要素（言語属性付き）
   * head要素（メタ情報）
   * body要素（表示コンテンツ）
   
2. **head要素の構成**：
   * 文字エンコーディングの指定（meta charset）
   * ビューポート設定（meta viewport）
   * タイトル要素（文書の最初の行をタイトルとして使用）
   
3. **body要素の構成**：
   * header要素：主見出し（h1）を含む
   * main要素：文書の主要コンテンツを含む
   
4. **main要素内の構造**：
   * 複数のsection要素を平坦に配置（ネストなし）
   * 各セクションは見出し要素（h2, h3）で始まる
   * 段落要素（p）による説明文
   * 箇条書きはul/liタグで表現
   * 表はtable/tr/th/tdタグで表現（border="1"属性付き）
   
5. **見出し階層**：
   * h1：ページ全体のタイトル（文書の最初の行）
   * h2：主要セクションの見出し（X. タイトル形式）
   * h3：サブセクションの見出し（X.Y タイトル形式）

## 変換ルール

1. **見出しの認識（非構造化テキスト対応）**：
   * 明示的なパターン：
     - 数字+ドット+スペース（例: "1. ", "2. "）→ h2見出し
     - 数字+ドット+数字+ドット+スペース（例: "1.1 ", "2.3 "）→ h3見出し
     - 行頭に「第X章」「X．」などの章・節を示す表現がある → 見出し
   * 暗黙的な特徴：
     - 短い行（概ね30文字以下）で次の行に説明文が続く → 見出しの可能性が高い
     - 空行を挟んで前後に長文がある短い行 → 見出しの可能性が高い
     - 全体的に短い文章が続いた後の、特に重要そうな短文 → 見出しの可能性が高い
     - 文書の論理的区切りを示す内容（「結論」「まとめ」「背景」「方法」など）→ 見出しの可能性が高い
   * 見出しのレベル判断：
     - 文書の最初の行は通常h1（タイトル）
     - 文書の論理構造に基づいて階層を推測（主要な区切り→h2、詳細な区切り→h3）
     - 文体や重要度から階層を推測（より簡潔・包括的→上位見出し、より詳細・具体的→下位見出し）
   * 各見出しは新しいsectionを開始（ネストしない）
   
2. **リストの認識**：
   * アスタリスク（*）で始まる行を箇条書きリストとして認識
   * 連続する箇条書きは単一のulタグ内に配置
   
3. **表の認識**：
   * 表形式のデータはtableタグに変換
   * 行の区切りは明確な改行
   * 列の区切りはスペースとして扱う
   * 最初の行は見出し行（thタグ）として処理
   
4. **段落の認識**：
   * 見出し、リスト、表以外の連続するテキストは段落（p）として処理
   * 空行は段落の区切りとして扱う

## 重要な注意点

- スタイルシートは含めず、セマンティックなHTML5要素のみを使用
- すべての要素は適切に入れ子構造にする（ただし、sectionはネストしない）
- 言語属性は入力テキストの言語に合わせて設定（デフォルトは"ja"）
- 表は常にborder="1"属性を持つこと
- 変換後のHTMLはインデントを適切に設定し、可読性を高めること
- すべての文字エンコーディングはUTF-8を使用
- 文書構造に忠実に従い、情報を省略しないこと

## 非構造化テキスト処理のガイドライン

- **文書の構造推測**：
  - 文脈、内容、形式から文書の論理構造を推測する
  - 文章の長さ、段落の区切り、キーワードなどから見出しと本文を区別する
  - 空行や改行パターンから段落の区切りを認識する

- **見出しの判断基準**：
  - テキストの簡潔さ（見出しは通常短い）
  - 後続する詳細説明の有無（見出しの後には説明が続くことが多い）
  - 文脈上の重要性（主要な概念や区分を示す文）
  - テーマの転換点（新しいトピックの開始を示す文）

- **テキスト分析アプローチ**：
  1. まず文書全体を概観し、大まかな構造を把握する
  2. 論理的な区切りを特定し、見出しの候補を抽出する
  3. 見出し候補の階層関係を推測し、h1/h2/h3を割り当てる
  4. 残りのテキストを段落、リスト、表などに分類する

## 例

以下のような入力があった場合：

```
2024年果汁飲料市場トレンド分析
1. 市場概況
市場は拡大傾向にあります。
2. 主要トレンド
2.1 健康志向
* 低糖製品
* 機能性飲料
```

以下のようなHTMLを出力します：

```html
<!DOCTYPE html>
<html lang="ja">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>2024年果汁飲料市場トレンド分析</title>
</head>
<body>
    <header>
        <h1>2024年果汁飲料市場トレンド分析</h1>
    </header>
    <main>
        <section>
            <h2>1. 市場概況</h2>
            <p>市場は拡大傾向にあります。</p>
        </section>
        <section>
            <h2>2. 主要トレンド</h2>
        </section>
        <section>
            <h3>2.1 健康志向</h3>
            <ul>
                <li>低糖製品</li>
                <li>機能性飲料</li>
            </ul>
        </section>
    </main>
</body>
</html>
```

入力された文章を上記の仕様に従って、正確にHTMLに変換してください。

# 文章構造化プロンプト

以下の入力文章を指定された構造化フォーマットに変換してください：

## 入力フォーマット
任意のテキスト文章

## 出力フォーマット
以下の構造を持つマークダウン形式の文書：

1. 最初に全体を表す適切な**タイトル**を1行で作成してください
2. 内容を論理的に区分けした**番号付き主見出し**（例: 1., 2., 3.）を作成してください
3. 各主見出しの下に関連する**本文テキスト**を配置してください
4. 必要に応じて**サブ見出し**（x.y形式）を作成し、その下に詳細情報を記載してください
5. サブ見出しには必要に応じて**本文テキスト**や**箇条書きリスト**を含めてください
6. データが存在する場合は**表形式**で提示してください（ヘッダー行と複数のデータ行）
7. 一部の主セクション内には**箇条書きリスト**を含めることも可能です

## 出力例
```markdown
# [全体を表すタイトル]

## 1. [第一の主見出し]
[この主見出しに関連する本文テキスト...]

### 1.1 [サブ見出し]
[このサブ見出しに関連する本文テキスト...]
- [箇条書き項目1]
- [箇条書き項目2]
- [箇条書き項目3]

## 2. [第二の主見出し]
[この主見出しに関連する本文テキスト...]

### 2.1 [サブ見出し]
[このサブ見出しに関連する本文テキスト...]

| [列1名] | [列2名] | [列3名] |
|---------|---------|---------|
| [データ1] | [データ2] | [データ3] |
| [データ4] | [データ5] | [データ6] |

## 3. [第三の主見出し]
- [箇条書き項目1]
- [箇条書き項目2]
- [箇条書き項目3]
```

## 変換時の注意点
1. 原文の内容や文脈を維持しながら、読みやすく論理的な構造に再編成してください
2. 内容に応じて主見出しとサブ見出しを適切に設定してください
3. データは可能な限り表形式に整理してください
4. 箇条書きリストは関連性の高い項目をグループ化してください
5. マークダウン記法を正確に使用してください
6. 日本語・英語どちらの入力にも対応してください
